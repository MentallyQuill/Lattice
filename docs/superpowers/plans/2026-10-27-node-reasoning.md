# Node reasoning implementation plan

1. Register native reasoning controls for every potentially model-calling node
   and Generate Reply. Keep deterministic modes editable without losing saved
   values, and omit additive defaults from pinned definition identities.
2. Implement a pure provider/model option and request translation contract.
   Verify None, mandatory thinking, native effort names, Custom validation,
   host adapter mappings, and unsupported-value errors with payload assertions.
3. Project effective provider/model metadata into the inspector after static
   field caching. Add Custom text editing and preserve readonly, inherited,
   instance, undo/redo, and mode-switch behavior.
4. Attach reasoning centrally to auxiliary requests and nested helper requests;
   apply translations after preset conversion. Add an owned final settings
   hook for Generate Reply, preserving unrelated host payload additions.
5. Refresh generated fixtures, document actual adapter limits, review the diff,
   and run Node tests, type/build/assets checks and focused browser tests.

Independent implementation ownership: provider contract; UI projection/editor;
runtime/transport/native hook. Catalog, compatibility, integration, docs and
final verification belong to the coordinating agent.

Review focus: None is not a false promise of disabling mandatory thinking;
custom effort never gets silently coerced; helpers use child settings; host
profile refresh does not reuse stale options; native hooks affect only their
current owned request and leave unrelated custom body fields intact.
