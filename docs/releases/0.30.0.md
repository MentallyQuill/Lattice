# Lattice 0.30.0

[All release notes](README.md)

New managed **Read File** nodes can start with useful story data automatically. Lattice reuses saved state when it exists, or creates a valid document from the current conversation and character when it does not.

## Files initialize themselves

- New managed readers default to **Generate from story**. Lattice builds a schema-valid document using the reader's format, schema and columns, plus bounded conversation and character context. Unknown story facts remain unspecified.
- Compatible saved chat state is reused before creating a managed file. Existing contents are preserved; malformed or unauthorized state is reported rather than silently replaced.
- Initialization uses the reader's selected or inherited model and completion limit. Each missing document makes at most one conditional request; existing saved files need no request. **Initialization instructions** can guide the generated contents.
- **Valid starting template** creates schema-valid contents without a model request. **Require a file** makes the reader a required reference input and reports a missing file.
- Generated contents remain temporary during the run. They are saved only when the result is accepted; previewing, rejecting, cancelling or failing a run does not publish them. An accepted initialized document is reused on later runs.
- Private files keep their character scope. Nested systems and inherited schemas are supported. The combined-systems example uses **Require a file** for its authored effect library, holders and relationship rules.

Existing saved and external files remain in place. Explicit file paths and bindings stay authoritative, including missing, revoked or unavailable bindings; those remain errors instead of being replaced automatically.

## Verification

Verification used mocked providers and temporary or in-memory files; it made no live model-provider requests and did not change the installed extension, live settings, chats or user files. The fresh full unit run passed all 463 files. The newly added install-boundary smoke test also passed separately (2/2). Browser journeys passed (22/22), type checking reported zero errors and warnings, and the production build and packaged import checks (957 imports) passed. Generated memory examples remained unchanged (two lessons and ten files). The standard install smoke check passed against a temporary installed copy, with no errors, missing files or provider calls.

## Update

Update Lattice through SillyTavern's **Manage Extensions**, then reload every open SillyTavern page, including mobile browsers. Existing files and explicit file choices remain configured. New managed readers can use the initialization controls in **Details → File**.
