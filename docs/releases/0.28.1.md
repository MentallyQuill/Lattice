# Lattice 0.28.1

Model nodes can recover from temporary request failures and malformed structured output without restarting completed workflow steps.

## Per-node retries

Set **Maximum retries** on a model node to 0, 1 or 2. The default is 0, so existing workflows retain their request budgets. Two retries allow at most three physical requests for that node; every attempt is included in the workflow maximum and run details.

Known temporary network failures and HTTP 408, 429, 500, 502, 503 and 504 can retry with a short delay. Invalid model JSON or a schema mismatch can receive one corrective request within the same limit. Authentication, configuration, privacy and binding failures, truncated or unverified completions, and downstream validation failures stop. Native SillyTavern generation and Apply are not retried.

## JSON and diagnostics

Structured model output accepts one complete JSON document inside a JSON or unlabeled Markdown fence, with an optional leading BOM. The existing size limits and strict schema validation still apply. Prose around JSON, incomplete documents and invalid fields remain rejected.

Workflow and startup failures produce persistent, dismissible notices. Run details distinguish schema failures from an unsupported chat source and explain how to proceed. Notices expose bounded codes and node identifiers, without provider response text or scene content.

## Chat progress

A compact progress meter beside the chat box shows the active workflow stage and auxiliary requests without opening the canvas. It supports automatic Send and manual runs, clears stale progress on restart, and fits narrow mobile layouts.

## Mobile startup

Lattice uses secure random bytes when the browser does not expose crypto.randomUUID, allowing the launcher to start on ordinary LAN HTTP connections.

Reload all open SillyTavern pages after updating, including mobile browsers. Enable retries on the nodes where you want them.
