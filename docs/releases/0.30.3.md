# Lattice 0.30.3

[All release notes](README.md)

Authenticated host-file reads now recover more clearly from temporary connection problems.

## Host-file read recovery

- Temporary network or response-body errors, plus HTTP 408, 429, 500, 502, 503 and 504 responses, receive up to three read attempts. Lattice does not automatically repeat writes or model requests.
- Persistent connection failures, access denials and invalid metadata retain specific error codes and clearer messages instead of an unknown **FILE_STORAGE_FAILED** fallback.
- Read recovery does not rewrite saved files. Failures recorded by older versions may lack the request details needed to identify their original cause.
- Automatic managed-file initialization and connected writes use LAN HTTP-compatible UUID and SHA-256 helpers when `crypto.randomUUID` and `crypto.subtle` are unavailable. Saved fingerprint and intent formats are preserved; secure random values remain required.
