# Lattice 0.29.1

[All release notes](README.md) · [Changes since 0.29.0](https://github.com/MentallyQuill/Lattice/compare/dfbf4ab...main)

Workflows now save automatically inside SillyTavern, new output nodes have working file destinations, and common model JSON syntax errors can be repaired locally. This release includes the file-storage, recovery, example and workspace improvements made since [0.29.0](0.29.0.md).

## Automatic workflow saving

- Workflow designs live in a saved library inside SillyTavern. Initial drafts and later edits autosave, with **Saved in SillyTavern**, **Unsaved draft**, **Saving…** and **Save needs attention** showing the actual save status.
- **File → Open saved…** opens an existing workflow. Several chats can use the same saved design while keeping their story state separate. **Save As…** creates an independent copy; **Rename workflow…** keeps its identity.
- Failed or conflicting saves retain the draft. Before execution, Lattice reconciles the workflow selected for the current chat, including when the editor is closed. A conflicting recovery draft requires a visible choice instead of running the wrong workflow.
- **Download / share workflow…** creates a portable copy without machine paths, local connection identifiers or writable file bindings. **Download workflow backup…** retains local authoring configuration; file contents and their recovery history need separate backups.
- New workflows can be created during a native run without replacing that run's captured workflow. Initial saving and chat selection are ordered so a clean new draft is saved and selected correctly.

## Files work without manual setup

- New output and story-state nodes receive automatic destinations, friendly names, matching filename suffixes and valid initial state. **Write to File** now defaults to its own destination; **Connected document** remains available for an exact Read File reference. **Clock Commit** inherits its Story Clock destination.
- **Details → File → File handling** offers **Replace** and **Append**. Structured appends preserve valid data and accepted retries avoid duplicate additions. Existing specialized mutations remain available under **Advanced**.
- An unknown personal input offers **Import from device…** or an existing source choice. Importing creates a managed copy; later changes to the original device file do not change that copy.
- File controls provide **Change…**, **Open** and **Download**, automatic types, and character selectors for private access. Renaming a label keeps the physical destination stable; changing an existing type or destination uses an explicit new-copy flow.
- Existing chat data, browser grants, configured server paths, privacy restrictions and accepted history are preserved. Legacy intent is migrated before file preflight, valid legacy default targets remain usable, and managed access is rechecked after asynchronous preparation. An unavailable external destination is reported instead of silently redirected.
- The old global Workflow Data / Legacy chat data setup screen is retired; file choices belong to the nodes that use them.

## Storage choices and optional server setup

On first use, choose **Save only inside SillyTavern** or **Save anywhere on this computer**. Default storage creates real files in the authenticated user's SillyTavern files area without browser file APIs, experimental flags or an extra server component. **File → File storage…** changes the choice or resumes optional setup.

Custom locations use the machine running SillyTavern. The included setup ZIP provides Windows, macOS and Linux launchers, verifies the installed component, preserves unrelated configuration and backs up configuration before an explicitly authorized server-plugin setting change. Restart SillyTavern and use **Check again** to finish. Cancelling optional setup leaves default storage available.

The server folder chooser supports browsing, manual paths and authorized roots, including remote installations without a desktop file dialog. Refreshing status preserves the current folder. Setup distinguishes missing or outdated support from denied access and connection failures. Checked server writes retain receipts and interrupted-write metadata across browser changes and server restarts.

Inside-SillyTavern saves verify their acknowledgement, but independent browsers can still race; the optional server service serializes checked writes. See [storage and saving](../file-storage.md) and [server setup](../server-files.md) for the access rules and limits.

## Recovery and story-state history

- History maintenance runs automatically at accepted-save boundaries. Up to 20 prior content versions are retained separately from the history that prevents duplicate story effects.
- **File → Recover selected file…** inspects and confirms a previous version. Recovery checks the current destination and preserves privacy, accepted receipts and replay protection.
- Branching uses an exact verified publication point rather than substituting later story state. Missing verified history is reported instead of resetting a clock, ledger or progression record.
- Large server recovery transfers use bounded sessions, avoiding repeated full-history reads. Expired, obsolete or invalidated transfers are released, and recovery continues to check ownership and scope.
- Editing configuration, previewing or rejecting a result does not write output contents. Accepted Apply remains the save boundary, and uncertain saves retain explicit recovery handling.

## Repair common model JSON errors

**Model Call → Data**, model-mode **Extract** and **Enrich** try local syntax repair after strict parsing fails. Supported repairs include trailing commas, comments outside strings, single-quoted strings and literal newlines, tabs or other control characters inside strings. Repairs make no extra model request and appear as `MODEL_JSON_REPAIRED` in the run report.

Repaired output still passes the same schema, evidence, identity and size checks. Missing values, incomplete documents, ambiguous quotes, surrounding prose and multiple documents remain errors. Truncated or unverified completions remain rejected. The configured **Additional attempts** allowance still governs model correction when needed; local repair does not consume it. JSON Decode, authored schemas, workflow imports and file contents continue to require strict JSON.

## Workflow controls, examples and reliability

- **When a node fails** now lives in the **Workflow** menu. It remains a global setting captured for the next run, with the existing fallback, stop and continue choices.
- Registered examples prepare isolated sample files and valid state automatically. Authored file choices are preserved, and prior sample clocks are reused only with verified example ownership. Imported graph text alone cannot claim those sample-file permissions.
- Refreshed lessons, the combined-systems workflow, node guides and troubleshooting text describe automatic destinations, input copies, Replace/Append and recovery.
- Opening, closing and passively refreshing the workspace avoid unnecessary validation and hidden prompts. Shelf-created nodes retain their creation presets, file diagnostics point to the current controls, and chat switching and delayed reads retain workflow freshness checks.
- Release notes now have a dedicated archive and navigation, including reconstructed notes for older versions.

## Update

Update Lattice through SillyTavern's **Manage Extensions**, then reload every open SillyTavern page, including mobile browsers. Versioned module and stylesheet URLs are updated together to load the matching 0.29.1 code.

Existing files and access choices remain configured. Use **File → File storage…** for optional wider location access, and rerun the included setup when an installed server component needs updating. A custom server location belongs to the server machine; device imports and downloads belong to the browser device.
