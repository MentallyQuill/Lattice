# Lattice 0.29.0

[All release notes](README.md)

Choose files directly from the nodes that use them, decide how a workflow handles failed nodes, and configure reasoning for each model step. Details also has slimmer structured editors and clearer groups.

## Files belong to their nodes

Select a file-related node and open **Details → File**. Enter a **Filename**, then use **Choose location…** or **Open existing…**. The panel also provides format, missing-file behavior, initial content, and visibility. Missing destinations, permissions, or conflicting shared settings appear as **Setup Required** above the node; click it to open the relevant settings. Configured filenames remain visible above the canvas card.

- **Read File** owns its source file.
- **Write to File → Destination → Connected document** uses the exact incoming live reference and remains the default. Choose **Own file** to configure a destination without adding a separate reader.
- **Story Clock** owns its JSON file; **Clock Commit** inherits that captured destination.
- **Outcome Commit** owns its JSON ledger. **Random Pick** can use a configured ledger for persistent outcomes.

Choosing files, saving settings, previewing, and rejecting a result do not write document contents. Accepted **Apply** retains the existing authorization and version checks. A durable local journal records pending writes and receipts so an interrupted save can be reconciled without repeating a confirmed append. External file changes can invalidate a captured result.

Native browser file access and durable local storage are required. File handles stay in the browser’s local storage. Portable workflow exports retain suggested names and formats but remove local binding authority, so imported workflows need their files chosen again.

Existing chat documents and history remain available through **Workflow → Configure → Legacy chat data…**. Migration starts from saved content rather than the original template. Matching files can retain validated history and receipts; unrelated files do not inherit old save authority. The original chat data remains intact. **File Input** continues to import a snapshot; **Format** and **Project Document** continue to transform data without saving it.

## Choose what happens when a node fails

In **Extensions → Lattice → When a node fails**, choose:

| Option | Behavior |
| --- | --- |
| **Fall back to SillyTavern** | End workflow processing and allow ordinary SillyTavern generation. This remains the default. |
| **Stop all generation** | Stop the workflow and generation belonging to the current Send, including its group speakers and automatic continuation. |
| **Continue where possible** | Keep completed results and continue branches whose required inputs remain available. |

The preference is global, stays outside workflow files, and is captured at the start of each run. Changing it affects the next run.

**Continue where possible** works with authored optional Compose and Join inputs: omit a failed contribution or use its configured fallback. Required failed inputs block their consumers. Successful nodes are not rerun, and requests inside a failed multi-request node do not become partial outputs. Recovered runs show **Completed with failures** and retain their diagnostics and review controls. If the required generation or output path cannot survive, the Send stops. Cancellation, stale sources, privacy, and capability failures remain fatal; failed branches cannot publish writes. A completed native reply never triggers another fallback generation.

Node-local retries finish before this policy takes effect. Under **Limits & retries**, **Additional attempts** accepts 0–5, with 0 as the default. Five allows at most six physical requests including the first attempt. Eligible transient failures and at most one JSON/schema correction share that allowance; every request counts against the workflow budget. Native SillyTavern generation and Apply are not retried.

## Reasoning follows the model

Model nodes and **Generate Reply** expose **Details → Limits & retries → Reasoning**. Choices follow the effective provider, model, and installed SillyTavern adapter. Configure the actual model node inside a helper or subgraph; its retries retain the same reasoning controls.

**None** is the default. It disables optional thinking where supported. Models that require reasoning use their supported minimum or provider default, explained beside the selector. Hiding reasoning text does not disable reasoning computation.

**Custom** accepts a provider effort string of up to 128 characters. The saved text survives connection, model, and effort changes. Custom is subject to the adapter’s limits; unsupported values fail before the request rather than silently changing meaning. Native Generate Reply also requires the host’s final chat-settings event to apply an enabled override.

Rules use known model families and adapter behavior; Lattice does not fetch live provider catalogs. See [provider behavior and limits](../reasoning-controls.md) for supported routes, mandatory reasoning, custom endpoints, and auxiliary completion-verification restrictions.

## Easier inspection and review

Schema fields, typed values, lists, records, questions, and schedules expand inline with compact summaries and purpose groups. Long editors scroll within narrow sidebars. **Save** and **Discard** make drafts explicit; read-only bodies still allow inspection. Model Call keeps saved schemas and unfinished drafts when switching between **Plain text** and **JSON data**, and validates output changes with their connected wires.

Other improvements since [0.28.1](0.28.1.md) include:

- **Automatically apply revised reply** on Review / Publish can add and select a revised swipe after a successful Send. **Automatically accept story changes** separately accepts connected effects when the reply is unchanged. Both default off; manual review remains available.
- **Workflow → Run details… → Saved logs** retains bounded failure metadata locally. **Save model responses** separately opts into response-text capture and successful/cancelled logs. Turning it off stops response capture; existing logs remain until cleared or evicted.
- Schema correction receives bounded field-level diagnostics. Chat-bound derived context detects changes to the covered conversation prefix and uses its initial template for rebuilding.
- Live runs remain active when the editor is hidden, and failure details describe the recorded run.
- File-setting drafts survive unrelated node edits, shared private destinations accept equivalent imported settings, and native generation rechecks selected files after preparing guidance.

## Update

Update Lattice through SillyTavern’s **Manage Extensions**, then reload every open SillyTavern page, including mobile browsers.

Existing workflows keep the default fallback policy and zero additional attempts. Review **Reasoning** for model steps that need thinking enabled. New file nodes require explicit file setup; existing chat data remains in **Legacy chat data…** for continued access and migration. After importing a portable workflow, changing browsers, or losing file permission, choose its local files again before running. Keep automatic reply and story-change acceptance off unless you want those behaviors.
